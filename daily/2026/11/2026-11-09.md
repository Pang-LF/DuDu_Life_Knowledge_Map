昨天我们建立了一个质量门：Known Good Die / KGD（已知良品裸片）不是绝对完美，而是在指定测试边界下值得继续投入的 Die。今天进入新的 Module（模块）——Packaging, Memory & Accelerators（封装、存储与加速器）：它研究合格裸片怎样经过机械固定、供电、散热和高密度互连，变成 CPU、GPU 或 AI Accelerator（人工智能加速器）。

这个模块进入五年地图，是因为现代计算能力越来越不由单颗晶体管或单片 Die 决定，而由 Logic Chiplet、I/O Die、HBM、Interposer、Substrate、Power Delivery 与 Cooling 能否作为一个系统共同工作决定。今天先学母概念 Advanced Packaging（先进封装）与它的第一个核心机制 Compound Yield（组合良率）；下一步才能理解 HBM 为什么同时是带宽解决方案和制造瓶颈。

# Mastery Core（掌握核心）

## 1. Opening Puzzle（开场谜题）：切成八块，良率真的会凭空提高吗？

假设我们需要 600 mm² 的逻辑功能。方案 A 把所有功能做在一颗 600 mm² Monolithic Die（单片裸片）上；方案 B 把它拆成八颗 75 mm² Chiplet，再装进一个封装。

直觉会说：小 Die 良率更高，所以方案 B 一定更好。

先别急着下结论。若每一颗小 Die 都必须成功，而且我们随机拿八颗组装，那么八颗同时没有缺陷的概率，可能恰好与一颗相同总面积的大 Die 没有缺陷的概率一样。拆分没有让缺陷消失，它只是改变了失败发生时我们能保留什么。

## 2. Follow One Package（先跟随一个封装）

跟随一颗由八颗 Compute Chiplet 和一颗 I/O Die 组成的处理器。

晶圆测试后，Die Sorter（裸片分选机）根据 Wafer Map 只挑出已接受 Die。每一颗裸片被切割、搬运、放置并固定到 Package Substrate（封装基板）或 Interposer（中介层）上。它们通过微小凸点、铜连接与基板走线交换数据和电力；封装再把高密度内部连接转换成主板可使用的较大间距引脚或焊球，同时提供机械保护与散热路径。

直到 Final Test（终测）结束，我们才知道这些分别通过测试的部件，能否作为一个 Package（封装成品）共同启动、通信、达到频率和功耗要求。

问题因此从“每颗 Die 是不是好”变成三层：

1. **Component Yield（部件良率）**：每种 Chiplet、I/O Die、HBM 或其他部件有多少可用单位？
2. **Assembly Yield（组装良率）**：搬运、对准、键合、Underfill（底部填充）、基板和封装步骤是否成功？
3. **System-in-Package Yield（封装系统良率）**：所有 Die、互连、电源、时钟、热路径与测试条件是否共同满足最终规格？

## 3. 先定义 Advanced Packaging（先进封装）

传统 Packaging（封装）已经需要保护裸片、连接电源与信号、散热并提供可焊到主板的外形。Advanced Packaging（先进封装）并不是“包装更漂亮”，而是封装本身承担更多系统集成功能：把多颗不同 Die 以高密度、低延迟和可制造的方式连接起来，使它们共同表现为一个产品。

今天需要分清三个常见结构：

### Multi-Chip Module / MCM（多芯片模块）

多颗 Die 放在同一个封装中，通过有机基板或其他封装布线连接。它比主板级连接更紧密，但连线密度、距离和功耗取决于具体封装技术。

### 2.5D Integration（2.5D 集成）

Logic Die 与 HBM 等部件并排放置在 Silicon Interposer（硅中介层）或高密度 Redistribution Layer / RDL（重布线层）上。中介层像一块非常精细的内部布线平台，让大量短连接跨越不同 Die，却不要求逻辑 Die 彼此垂直堆叠。

### 3D Integration（3D 集成）

Die 垂直堆叠，并通过 Micro-bump（微凸点）、Hybrid Bonding（混合键合）或 TSV / Through-Silicon Via（硅通孔）等方式连接。它缩短距离、提高连接密度，却让热、测试、对准、返工和良率更困难。

这三类不是严格的价值排名；产品应根据带宽、延迟、功耗、面积、散热、产量、成本和供应生态选择。

## 4. Chiplet 到底是什么？

Chiplet（芯粒）不是“任何小芯片”的时髦称呼。它通常是一块被设计为与其他 Die 通过明确定义接口共同组成更大系统的功能裸片。它可以承载 CPU Core、I/O、Cache、Memory Controller、Accelerator 或其他功能。

Chiplet 架构可能创造四类价值：

- **Harvesting（良品收割）**：小 Die 失败时只丢弃该小块，其他通过测试的 Die 仍可进入别的封装。
- **Process-node Mixing（混合制程）**：密集逻辑放在先进节点，I/O、Analog（模拟）或其他不按同比例缩放的功能留在更成熟节点。
- **Product Scaling（产品伸缩）**：同一种 Compute Chiplet 可以用不同数量组成不同 Core Count（核心数）产品。
- **Design Reuse（设计复用）**：验证过的模块和接口可跨产品复用，减少每个产品都重新设计整颗大 Die 的需要。

但它同时新增 Die-to-Die Interface（裸片间接口）、Package Routing（封装布线）、时钟与一致性、功耗、延迟、散热、测试和供应协调问题。Chiplet 是把一个大问题重新分解，不是删除问题。

## 5. Quantitative Mini-case（量化小案例）：为什么“八颗小 Die 都成功”并不解释收益？

继续使用 11 月 7 日的透明 Poisson 教学模型：假设致命缺陷独立、均匀分布，`Yield = e^(-D0 × Area)`，Defect Density `D0 = 0.10 defects/cm²`。这不是任何 AMD、Foundry 或封装产品数据。

一颗 600 mm² Die 是 6 cm²：

`Y_monolithic = e^(-0.10 × 6) ≈ 54.9%`

一颗 75 mm² Chiplet 是 0.75 cm²：

`Y_chiplet = e^(-0.10 × 0.75) ≈ 92.8%`

92.8% 看起来远高于 54.9%。但若随机拿八颗、要求八颗全好：

`P(all 8 good) = 0.928⁸ ≈ 54.9%`

结果与单片 Die 相同，因为总面积相同：`e^(-0.075 × 8) = e^(-0.6)`。这说明“小 Die 单颗良率高”不是完整解释。

### 真正变化的是失败后的可回收性

比较相同的总硅面积：100 颗 600 mm² Monolithic Die 对应 800 颗 75 mm² Chiplet。

- 单片方案预计得到约 `100 × 54.9% = 54.9` 颗 Good Die。
- Chiplet 方案预计得到约 `800 × 92.8% = 742` 颗 Good Chiplet。
- 742 颗 Good Chiplet 可以组成约 92 组八颗套件，剩余约 6 颗；失败的小 Die 不会把同组其他硅面积一起报废。

这才是 Harvesting（良品收割）的核心：先测试，再跨晶圆位置重新组合通过品。

### 但封装会重新收取“组合税”

再做一个假设：八颗 Compute Chiplet 与一颗 I/O Die 都已经是 KGD；九次放置与互连步骤各有 99.5% 成功率，之后基板、Underfill 与最终封装整体步骤有 99% 成功率：

`Assembly Yield ≈ 0.995⁹ × 0.99 ≈ 94.6%`

92 组 KGD 输入最终预计产生约 `92 × 94.6% ≈ 87` 个成功封装。Chiplet 方案在这个模型中仍高于单片方案的约 55 颗，但收益从 92 降到了 87；若互连良率、KGD Escape、封装成本、功耗或散热更差，优势会继续缩小甚至反转。

这个模型忽略晶圆边缘、缺陷聚集、不同功能面积、冗余、参数分档、I/O Die 供给、测试成本、Die 间匹配和单片方案自身的封装良率。它只隔离一个机制：拆分价值来自可筛选与可重组，不来自概率魔法。

## 6. Compound Yield（组合良率）：每个局部高良率为什么仍可能得到低总良率？

当一个产品要求多个独立必要条件同时成立时，第一阶 Compound Yield（组合良率）可以写成：

`Y_total ≈ Y_die1 × Y_die2 × … × Y_interconnect × Y_package × Y_final_test`

乘法不是说现实因素一定独立。恰恰相反，共同温度、设备、材料批次、翘曲和污染会产生相关失效，使简单乘法过于乐观或错误。乘法的用途是提醒我们：每个 99% 看似很高，连续经过多个必要门以后，总体不会仍是 99%。

它也揭示 Bottleneck（瓶颈）会移动。今天缺的是 Good Compute Chiplet，明天可能变成 HBM Stack，后天可能是 Interposer、Substrate、Bonding Capacity 或 Final Test。拥有最多晶圆并不保证拥有最多可交付 Package。

## 7. Deep Case：AMD EPYC “Rome” Chiplet Architecture, 2018–2019

### Before：为什么把所有功能放进一颗 Die 曾经是理想？

单片 SoC（系统级芯片）让 Core、Cache、Memory Controller 和 I/O 在同一硅片上通信，避免跨 Die 接口和复杂封装。过去 Process Scaling（制程缩放）通常让更多晶体管以相对可控成本进入同一 Die，“集成更多”因此长期是性能和经济性的共同方向。

AMD 第一代 EPYC 7001 “Naples” 已使用多 Die 封装，最高提供 32 个 Zen Core。可是下一代若要增加核心数、进入 7nm，又需要重新决定哪些功能真正值得迁移到先进节点。

### Pressure Builds：为什么 I/O 与 CPU Core 不再适合一起缩放？

CPU Core 与 Cache 能从更高晶体管密度和能效中明显受益；大型 I/O、Memory Interface 和部分 Analog / Physical Interface 并不会按同样比例变小，迁入昂贵先进节点未必产生相同价值。

与此同时，核心数增加会扩大单片面积。更大 Die 暴露于更多致命缺陷机会，且每一颗失败都报废整块先进节点面积。可问题是：把功能拆开又会迫使所有 Core 通过封装互连访问统一的 Memory 与 I/O，架构和软件必须接受新的距离与延迟结构。

### Turning Point：AMD 把“一个处理器”重新定义为多个不同 Die

AMD 在 2018 年 Next Horizon 活动公开 “Rome”：使用最多 64 个 Zen 2 Core，把需要先进制程的 CPU Core 放在 7nm Chiplet，把 Input / Output 部分放在成熟 14nm 工艺，并用增强的 Infinity Fabric（无限架构互连）连接。

AMD 后续技术指南显示，一颗 EPYC 7002 处理器由一颗 I/O Die 和最多八颗 Core Complex Die / CCD（核心复合裸片）组成；每颗 CCD 最多包含两个 CCX，每个 CCX 最多四个 Core。最高配置因此是八颗 CCD、每颗八核，共 64 核。

### Cascade：拆开以后，哪些新问题必须同时解决？

首先，所有 CCD 需要被测试和分档，数量与性能要满足具体 SKU。其次，中央 I/O Die 必须可用；即使八颗 Compute Chiplet 全部合格，缺少 I/O Die 也不能形成处理器。

然后，封装必须准确放置九颗 Die，并让 Infinity Fabric、Memory、PCIe、Clock、Power 与 Cache Coherence（缓存一致性）工作。Core 到 Memory 的路径不再完全相同，NUMA（非一致性内存访问）与软件调度开始影响实际性能。物理拆分把一部分 Die 良率问题，转换成互连、封装和系统架构问题。

### Decision：为什么选择中央 I/O Die，而不是继续复制完整 SoC？

把 I/O 集中到一颗 Die，让每颗 CCD 专注于可重复的 CPU Core 与 Cache；相同 CCD 可以按 2、4、6 或 8 颗组成不同产品，中央 I/O 则提供统一 Memory 与 PCIe 能力。AMD 可以把 7nm 预算集中给最受益的计算逻辑，同时使用成熟制程承载 I/O。

代价是中央 I/O Die 成为共同依赖，Infinity Fabric 成为关键接口，Package Design、Power Delivery 和 Test Flow 更复杂。这个决策不是“先进节点好、成熟节点差”，而是让每种功能使用更合适的工艺与位置。

### Outcome：架构是否真的变成了产品？

AMD 于 2019 年 8 月推出第二代 EPYC 7002 系列，公开规格最高 64 个 Zen 2 Core；上一代 EPYC 7001 最高 32 Core。核心数翻倍不是单独的良率证明，却说明模块化架构已经越过演示，成为可出售、由服务器生态采用的产品。

AMD 将其描述为更具成本效益的制造方式，并强调 7nm Core 与成熟制程 I/O 的组合。公司没有公开 Rome 的产品级 CCD Yield、I/O Die Yield、Package Yield、每颗成本或与假设单片版本的严格反事实，因此我们不能从发布成功倒推出精确节省金额。

### Aftermath：Chiplet 为什么从制造技巧变成架构平台？

AMD 后续把 Chiplet 扩展到多代 EPYC 与 Ryzen 产品。IEEE 2021 年 AMD 论文把背景描述为传统缩放放缓、制造成本上升，以及系统从高度集成转向由多个较小 Chiplet 重新组合。

真正重要的变化不是“Die 变小”，而是设计团队开始把接口、验证、封装、测试和产品组合一起设计。封装从被动外壳变成 System Architecture（系统架构）的一部分。

## 8. 有意义的对照：Monolithic 与 Chiplet 各自把风险放在哪里？

| 维度 | Monolithic Die（单片裸片） | Chiplet Package（芯粒封装） |
|---|---|---|
| 缺陷损失 | 一个局部致命缺陷可能报废整颗大 Die | 可在组装前丢弃单颗坏 Chiplet，保留其他良品 |
| 制程选择 | 全部功能通常共享同一工艺 | 不同功能可以选择不同工艺节点 |
| 内部通信 | On-die 连接通常更短、更密 | Die-to-die 接口增加延迟、功耗与协议要求 |
| 产品伸缩 | 新核心数可能需要新 Die 或停用部分核心 | 可改变 Chiplet 数量与 Bin 组合 |
| 封装 | 相对简单，但大 Die 仍需供电与散热 | 放置、键合、基板、中介层、测试和散热更复杂 |
| 良率边界 | 主要由整颗 Die 与后续封装决定 | 由 KGD 供给、匹配、互连、组装和终测共同决定 |
| 供应链 | 依赖一条主要 Die 路径 | 任何一种 Chiplet、HBM、Interposer 或 Substrate 都可能成为短板 |

Chiplet 并不普遍优于单片。功能规模小、接口要求极高、产量有限或封装成本过高时，单片可能更简单、更低功耗也更便宜。正确问题是：在这个产品的面积、数量、工艺、带宽、延迟、功耗和供应边界下，哪种分解方式产生更多最终 Good Package。

## 9. Industry Apprenticeship：一颗先进封装的钱付给谁，权力来自哪里？

今天只回答一个行业问题：**当产品从一颗 Die 变成多个 Chiplet、Interposer、Substrate 与 HBM 时，谁提供什么，谁先承担失败，谁控制最稀缺的接口？**

Fabless 或 IDM 的 Product Architect（产品架构团队）决定功能怎样切分、接口怎样定义、哪些工艺承载哪些模块，并支付设计、IP、Mask / NRE、Wafer、测试和封装服务。若系统指标或接口设计错误，即使每个供应商都按规格交付，最终产品仍可能失败。

Foundry 制造各类 Die，有些 Foundry 也提供 Integrated Advanced Packaging（集成先进封装）。OSAT 可以提供 Bump、Assembly、Package Test 与可靠性服务。Substrate 与 Interposer 供应商制造高密度布线平台；Memory Vendor 提供 HBM Stack；ATE、Probe、Bonding、Inspection 与 Metrology 设备商提供制造和验证工具。

最终客户通常购买完整处理器或 Accelerator，不会分别向每个内部部件付款。Fabless / IDM 因此充当系统集成者：它向上游支付并承担库存、匹配和良率风险，再以合格 Package 的价格向下游销售。

议价权来自“可替代性最低且切换最慢”的合格能力：可能是领先逻辑晶圆，可能是 HBM，也可能是 CoWoS 类先进封装、Large Interposer、ABF Substrate（ABF 封装基板）、测试能力或共同设计数据。TSMC 的 CoWoS 公开架构显示，Logic Chiplet 与 HBM 可以通过 Silicon 或 RDL Interposer 集成；这类服务出售的不是单个物料，而是经过资格化的 System Integration Platform（系统集成平台）。

### 失败成本怎样分配？

如果一颗 Chiplet 在入料测试前失败，损失主要停留在该 Die。若 Bonding 后才发现，一次失败可能吞掉其他 Good Die、HBM、Interposer、Substrate、组装工时与产能。若 Final Test 以后才在客户系统暴露，还会叠加 Board、Server、Warranty 与交付损失。

合同可以规定 Die 按 Wafer、Known Good Die、合格 Stack 或 Final Package 计价，也可以包含质量、交付、返工与赔偿边界；这些条款通常保密。公开技术图无法告诉我们某一 NVIDIA、AMD、TSMC、OSAT 或 HBM 供应商在具体产品中承担多少 Scrap 或 Warranty。

## 10. Practitioner Metrics（从业者真正看的数字）

- **KGD Availability（已知良品可得量）**：不是投片数，而是满足接口、档位和测试条件的可组装 Die 数量。
- **Die Match Rate（裸片匹配率）**：不同 Bin、Leakage、Power 或版本的 Die 能否组成目标 SKU。
- **Placement / Bond Yield（放置 / 键合良率）**：每次搬运、对准和连接有多少成功。
- **Package Yield（封装良率）**：投入 KGD 与封装材料后，有多少完整 Package 通过终测。
- **Reworkability（可返工性）**：失败后能否移除并替换部件，还是整包报废。
- **Cycle Time（周期）**：最慢 Die、HBM、Substrate、Interposer、Assembly 或 Test 阶段何时齐套。
- **Cost per Good Package（每个良品封装成本）**：所有 Die、封装、测试、报废和资本成本由最终通过品分担。

任何“封装产能翻倍”的声明都要继续问 Product Mix、Package Size、Layer Count、HBM 数量、Yield 与 Cycle Time；设备数量或投入面积不等于最终 Good Package。

## 11. Fact、Interpretation、Inference 与 Hypothesis

> **Fact（事实）**：AMD 在 2018 年公开 Rome 使用 7nm CPU Core Chiplet、成熟 14nm I/O 与 Infinity Fabric；技术指南记录 EPYC 7002 由一颗 I/O Die 与最多八颗 CCD 组成；2019 年推出的产品最高 64 Core，上一代最高 32 Core。TSMC 公开资料把 CoWoS 描述为通过 Interposer 集成 Logic 与 HBM 的先进封装平台。

> **Interpretation（解释）**：Chiplet 的经济价值来自可筛选、可重组、可混合工艺和可复用，而不是让相同总面积的随机缺陷概率自动消失；最终产出取决于 KGD、组装与系统共同成功。

> **Inference（推断）**：随着 Logic Die、HBM 数量、Interposer 面积和封装步骤增加，控制跨部件测试数据、接口规则与高良率集成能力的企业会获得更强议价权。具体权力仍随产品和替代能力变化。

> **Hypothesis（仍需验证的假设）**：Rome 相对一个功能相同的单片 7nm 设计节省了某个精确百分比的成本，或其成功主要由良率单一因素造成。AMD 没有公开足够的反事实成本、产品级良率和封装数据来识别这个数字或单一原因。

## 13. Transfer（迁移）：以后看到“Chiplet 降低成本”，先问什么？

1. **切分边界**：哪些功能被拆开，为什么它们适合不同面积或制程？
2. **KGD**：每种 Die 的真实可用量和 Bin Mix 是什么，测试覆盖到哪里？
3. **组合路径**：一套 Package 需要多少 Die、HBM、Interposer 与 Substrate？
4. **新增损失**：Die-to-die、Bonding、Warpage（翘曲）、Power、Thermal 与 Final Test 增加什么失败机会？
5. **回收与返工**：失败时能保留哪些部件，哪些价值会一起报废？
6. **经济分母**：比较的是 Wafer Cost、Good Die、Good Package、性能、功耗还是完整系统成本？

## Industry Vocabulary（今天真正需要记住的行业词）

**Chiplet（芯粒）**：被设计为通过明确接口与其他 Die 共同组成系统的功能裸片。它历史上回应大 Die 成本、制程异质性和产品复用问题；产品公司支付设计与集成成本，受益于收割良品、混合节点和组合 SKU。常见误解是“小 Die 自然等于低成本”。

**Interposer（中介层）**：位于多个功能 Die 与 Package Substrate 之间的高密度布线平台，可以是 Silicon 或 RDL 等形式。它解决主基板线宽和连接密度不足的问题；常见误解是把它当成主动计算 Die，或认为所有多 Die 封装都必须使用硅中介层。

**Package Substrate（封装基板）**：把封装内部的高密度信号、电源和机械结构扇出到主板连接的载体。产品公司通过封装供应链付款，基板商和组装方受益；它解决电气、机械和可焊接接口问题，不只是“托住芯片”。

**Compound Yield（组合良率）**：多个必要部件与步骤共同成功的最终比例。它帮助把局部良率转换为 Good Package；常见误解是直接相乘而忽略相关失效、返工、冗余、匹配和测试误差。

**Known Good Die / KGD（已知良品裸片）**：在给定测试边界下被接受的组装输入。先进封装方愿意为更可信的 KGD 付费，因为一颗 Escape 可能毁掉其他昂贵部件；但 KGD 仍不是永久可靠保证。

## Teach-back（20-30 分钟讨论）

1. 一家公司把一颗 800 mm² AI Die 拆成四颗 200 mm² Logic Chiplet，却发现 Cost per Good Package 上升。请沿 KGD、Bin Matching、Interposer、HBM、Bond Yield、Final Test、Power 与 Cycle Time 构造至少四条机制，并说明需要什么证据区分它们。
2. 两个方案总逻辑面积相同：A 是一颗大 Die，B 是八颗小 Die。请不用“小 Die 良率高”一句带过，完整解释为什么随机组合时概率没有改善、为什么先测试再重组可能改善、以及什么新增成本会让结论翻转。

# Connection Preview（连接预览，不正式教授）

- **HBM, TSV & Memory Bandwidth（高带宽存储、硅通孔与内存带宽）**：多个 DRAM Die 怎样堆叠，并通过宽接口靠近 Accelerator。
- **Thermal & Power Delivery（散热与供电）**：更多 Die 和 HBM 如何形成不均匀热密度与供电约束。
- **UCIe & Interface Standards（芯粒互连接口标准）**：开放接口何时可能把一家公司内部的 Chiplet 变成多供应商生态。
- **Supply-chain Bottleneck（供应链瓶颈）**：先进逻辑、HBM、Interposer、Substrate 与封装产能中哪一项决定最终出货。

# Closing the Loop（闭环）

**现在我们可以重新回答开头的问题**：把 600 mm² 功能切成八颗 75 mm² Chiplet，不会让相同总面积的随机缺陷概率凭空消失；它的价值来自先测试、丢弃失败小块、跨位置重新组合 Good Die，并让不同功能选择不同工艺。作为交换，产品必须支付 Die-to-die、Interposer、Substrate、Bonding、Power、Thermal、Test 与 Compound Yield 的新成本。
