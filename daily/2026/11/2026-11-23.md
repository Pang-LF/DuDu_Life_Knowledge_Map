# Mastery Core（掌握核心）

## 1. Opening Puzzle（开场谜题）：客户把钱付给 AWS，为什么 NVIDIA 仍可能保留巨大价值？

想象一家企业在云上购买一次 AI Inference（人工智能推理）。它没有向 Wafer Supplier、Foundry、HBM Manufacturer 或 NVIDIA 分别下单；它只看见一个 API、一个模型结果和一张 Cloud Bill。客户关系在 Cloud Provider 手里，为什么上游芯片平台还能获得很高收入与毛利？反过来，既然 NVIDIA 的平台已经成熟，AWS 为什么还要投入 Trainium 自研芯片，而不是只做最靠近客户的软件与计费？

如果把产业链理解为“越靠近客户越有权力”，第一个现象难以解释；如果理解为“最难制造的芯片拿走全部价值”，第二个现象又难以解释。真正的问题不是谁最上游或最下游，而是：**谁控制了一项系统必须经过、短期又难以替代的合格转换？谁还能把这个控制转成价格、合同、数据、软件生态或客户关系？**

今天先跟随一次成功的推理请求。它是最小单位，也是最终客户真正愿意付款的对象。我们从结果向物理世界逆行，寻找每一层到底交付了什么。

## 2. 先定义母概念：Value Chain 是连续的合格转换，不是公司名单

**Value Chain（价值链）**是多个不同参与者把资源、信息和能力逐层转换为客户愿意付款的产品或服务的系统。每一层既接收上游交付物，也要把它转换成下游能够验收的新对象。

“合格”是定义里的关键。Wafer 不是有硅就够了，而要满足晶向、表面、缺陷和客户资格；Fabricated Die 不是图形印上去就够了，而要通过电性与良率要求；HBM 和 Logic Die 不是放进同一封装就够了，而要在互连、热、功耗和最终测试上工作；Server 不是部件装齐就够了，而要通过 Firmware、Signal Integrity、Power、Cooling 和 Software Validation；Cloud Instance 不是机器通电就够了，而要被 Scheduler 放置、被 Network 到达、被 Identity 授权，并在约定性能和可靠性下完成请求。

因此一条价值链至少同时包含四种流：

- **Physical Flow（物理流）**：材料、晶圆、裸片、封装、板卡、服务器、机架和设施能力向下游移动；
- **Information Flow（信息流）**：设计、PDK、Test Data、Telemetry、Forecast、Qualification 和故障证据在各层双向移动；
- **Money Flow（钱流）**：最终客户付款后，Cloud Provider、System Integrator、Chip Designer、Foundry、OSAT、Memory、设备与材料供应商通过采购、合同、折旧和利润获得回报；
- **Control Flow（控制流）**：接口标准、Design Win、软件生态、资格记录、容量优先权、调度、计费、数据和客户关系决定谁能改变规则。

这一定义必须先于 Profit Pool。若不知道各层卖的对象不同，我们会把一美元收入错误地切成一张静态饼图；事实上，上游芯片可能多年服务许多请求，Cloud 资产经过折旧，合同有时间差，软件与支持也跨多个产品，公开财务无法把某一次 API 调用逐层对应到供应商利润。

## 3. Follow One Unit（跟随一个最小单位）：一次成功推理怎样回到一片晶圆？

### Cloud Software：把业务意图变成可计量请求

客户提交 Prompt 或数据，Cloud API 验证 Identity、Quota、Model 和 Region。Scheduler 为任务寻找可行资源，Runtime、Compiler、Library 和 Model Server 把请求变成 Accelerator 可以执行的算子。Cloud Provider 交付的不是“拥有一张卡”，而是在一个时间、位置、性能、可用性、支持和计费边界内完成请求。

### Data Center 与 Network：让资源在正确位置持续工作

请求需要 DNS、Routing、Load Balancing、Storage 和 Cluster Network 到达正确机器。机架需要可持续的 Critical IT Power、Cooling、Physical Space、Fire Protection 和 Operations。芯片即使库存充足，如果园区没有可用电力、液冷、交换机、光模块或 Commissioned Rack，仍不能变成可售 Cloud Capacity。

### Server：把异质部件变成一个可验收节点

System Integrator 把 CPU、Accelerator、Memory、NIC、Storage、Power、Cooling、Firmware 与 Management Software 组合起来，解决电源完整性、信号完整性、拓扑、启动、故障诊断和支持边界。合格交付物是一个稳定节点或 Rack-scale System，不是一袋昂贵部件。

### Accelerator、HBM 与 Packaging：把计算和数据移动放进同一可用系统

Accelerator 执行并行工作，但其 Useful Throughput 受 HBM Bandwidth、Capacity、Interconnect、Kernel、Precision 和 Software Mapping 约束。Advanced Packaging 要把 Logic Die、HBM Stack、Substrate / Interposer 和高密度互连组合为通过最终测试的 Package。某层数量增加而匹配层不足时，库存不会自动变成 Good Accelerator。

### Fabrication、Wafer 与上游设备材料：把设计变成 Good Die

Foundry 使用合格 Wafer，依靠 Lithography、Deposition、Etch、Doping、Metrology 和 Process Control 重复执行大量步骤。Wafer Starts 只有经过 Cycle Time、Defect、Parametric Distribution、Wafer Sort 和 Binning 才成为 Known Good Die。设备、光罩、化学品、气体、硅晶圆和工艺知识共同决定可复制的转换能力。

再回到用户：这条链并不是“一片晶圆对应一美元”。一块芯片在数年内服务许多请求；一座数据中心同时承载许多客户；某次请求还会消耗软件、网络、电力和人员。我们能可靠追踪的是**必要的合格转换**，不能从公开数据伪造逐请求的精确上游分账。

## 4. 一美元怎样进入价值链：先画账户，不先猜百分比

对一美元 Useful Cloud Service Revenue，最安全的第一阶账户是：

```text
$1.00 Customer Revenue
= Supplier payments embodied in service
+ Depreciation / leases for owned or contracted capacity
+ Power, facility, network and operations
+ Software, sales, support and administration
+ Idle, reliability and obsolescence risk carried by provider
+ Provider operating contribution
```

这不是说六项一定加总成公开报表中的同一口径。Inventory Recognition、Capex Depreciation、Lease、Stock-based Compensation、R&D 和 Segment Allocation 都可能跨期或跨产品。它的作用是阻止两个常见错误：第一，把 Cloud Revenue 当成硬件采购额；第二，把上游供应商 Revenue 当成 Cloud Provider 同期 Cost。

钱向上游移动时，每层购买的是新的合格对象：Cloud Provider 向 System / Chip / Facility 伙伴购买 Capacity，System Integrator 购买 Component 与 Support，Chip Designer 向 Foundry、Packager 和 Memory Supplier 购买加工与部件，制造商再向设备材料商购买能力。与此同时，设计、Forecast、Qualification、Warranty 和故障责任反向约束上游。

所以今天不制作“Wafer 2%、HBM 8%、GPU 35%”之类的饼图。没有同一产品、同一服务期、采购折扣、利用率、折旧、供应商成本和合同数据，这种精确感是虚构的。

## 5. Bottleneck Migration（瓶颈迁移）：产能增加为什么不保证服务增加？

假设 Cloud Provider 计划部署 128 个八卡节点，也就是 1,024 个 Accelerator Slot。现在给出一组完全透明的教学假设：

```text
Qualified accelerators available: 960 → at most 120 eight-card nodes
Server assembly and validation output: 116 nodes
Network, power and cooling capacity: 100 nodes
Average useful scheduler allocation: 85%

Useful-node equivalent = min(120, 116, 100) × 85% = 85
```

这组数字不是 NVIDIA、AWS 或任何客户数据。它只显示机制：1,024 个计划 Slot 并不等于 1,024 张可售卡；960 张合格卡也不等于 120 个可用节点；116 个节点若只有 100 个机架能被供电、冷却和联网，系统仍停在 100；Scheduler 平均只有 85% 转成有用分配时，最终只有 85 个 Useful-node Equivalent。

如果增加 Accelerator 到 1,200 张，最终仍是 85。此时 Accelerator 已不是瓶颈；电力、冷却或网络成为约束。若再扩充机房到 130 节点，Server Validation 的 116 又可能成为瓶颈。**Value Chain 的产出不是各层产能之和，而是经过匹配、资格化、时间和位置之后的共同可行集合。**

这个结论也解释了权力为什么会迁移。稀缺层扩产、替代品成熟或接口标准化以后，溢价可能下降；新的约束层则可能获得优先权、长约、预付款或更高议价能力。昨天最赚钱的层不保证永远控制明天的利润池。

## 6. Profit Pool（利润池）：什么样的层能把系统重要性变成经济回报？

**Profit Pool（利润池）**指一条产业链中各层能够保留的利润分布，不是 Revenue 分布。高收入层可能因资本、竞争和采购成本而利润薄；部件成本占比不高的层，也可能因稀缺接口、IP、资格记录或软件生态保留较高回报。

一层更可能保留利润，通常需要几项条件同时存在：

1. **Indispensability**：下游产出必须经过这项能力，不是可选功能；
2. **Qualified Scarcity**：合格替代供给少，扩产、良率爬坡或客户认证慢；
3. **Interface Control**：该层控制设计接口、软件栈、标准、数据或系统组合方式；
4. **Switching Delay**：替换需要 Porting、Qualification、Retooling、合同重谈或重新训练组织；
5. **Customer / Demand Control**：该层掌握 Billing、Usage Data、Distribution、Support 或终端客户关系；
6. **Risk Absorption**：该层真正承担库存、资本、可靠性、保修、技术过时或需求波动风险，并能因承担风险获得补偿。

只有“重要”并不够。电力对数据中心不可缺，却可能在竞争性批发市场中难以保留高利润；一款芯片技术先进，却可能因软件缺失和客户无法部署而没有价值；Cloud Provider 掌握客户，也可能因提前建设昂贵容量和快速折旧而承担巨大风险。利润是市场结构、合同和风险之后的剩余，不是工程重要性的自动奖章。

## 7. Main Case — NVIDIA 从芯片到数据中心平台：利润池为什么向系统接口移动？

### Before：2017 年的 NVIDIA 仍主要被看作 GPU 公司

NVIDIA FY2017 Form 10-K 显示，截至 2017 年 1 月 29 日的财政年度，总收入为 69.10 亿美元，其中 Datacenter 为 8.30 亿美元，约占 12.0%；Gaming 为 40.60 亿美元。公司合并 Gross Margin 为 58.8%。同年 NVIDIA 已在销售 Tesla P100、P40、P4、DGX-1 与 TensorRT，但数据中心尚不是收入主体。

这组数字的分母很重要：8.30 亿是 NVIDIA 的 Datacenter Revenue，不是全球 Cloud Revenue，也不是最终客户在 AI 上的总支出。58.8% 是公司合并毛利率，扣除了 Cost of Revenue，但没有扣除全部 R&D、销售和管理费用。

### Pressure Builds：GPU 变快以后，周围系统开始决定 Useful Throughput

Deep Learning 工作负载扩大后，客户需要的不再是孤立 GPU 峰值。模型要从 HBM 取数据，多卡要通过 Interconnect 和 Network 同步，节点要在 Power 与 Cooling 边界内运行，Compiler、Library 和 Framework 要把算子映射到硬件，Cloud Provider 还要把容量变成可计量服务。

这带来一个压力：若 NVIDIA 只交付 Processor，其他层的瓶颈会限制客户真正获得的性能，也让 System Integrator、Network Vendor、Cloud Provider 或 Software Platform 控制更多接口。要保留价值，NVIDIA 必须让自己的设计不仅在芯片 Benchmark 中快，也在完整系统里更容易被部署和持续利用。

### Turning Point：平台边界扩展到 Networking、System 与 Software

2020 年 4 月，NVIDIA 以交易价值 70 亿美元完成 Mellanox 收购，把高性能 Networking 纳入组合。NVIDIA FY2026 10-K 也把自己的 Data Center Platform 描述为由 GPU、CPU、DPU、NVLink、InfiniBand / Ethernet、Rack-scale System、CUDA、Library、API、SDK 和 AI Software 共同构成。

这是价值链中的边界选择。公司没有因此拥有 Foundry、HBM Fab、所有 Server Factory 或 Cloud Customer Relationship；它扩大的是自己能够协同设计和控制的接口。从 Processor 向 Interconnect、Networking、System Reference 与 Software Stack 扩展，使客户替换的不再只是一个 Part Number，而是一组共同工作、共同验证的技术和开发路径。

### Cascade：控制更多接口，也让依赖和资本承诺变得更大

Full-stack 不等于 Vertical Integration of Everything。NVIDIA 仍采用 Fabless 与 Contract Manufacturing Strategy，由 Foundry、Assembly、Testing、Packaging 和其他供应商完成制造；公司 10-K 明确提到 TSMC 与 Samsung 等 Foundry，并可能直接采购 Memory、Substrate 与其他 Component。

系统复杂度越高，对 Wafer、Advanced Packaging、Memory、Networking、Power、Cooling 和客户 Data Center Readiness 的同步要求越高。NVIDIA FY2026 披露截至 2026 年 1 月 25 日 Manufacturing、Supply 与 Capacity Commitments 为 952 亿美元，几乎全部预计在 FY2027 支付；这不是利润，而是为了未来供应承担的采购和预测暴露。公司也披露 FY2026 Inventory 与 Excess Purchase Obligation Provision 共 72 亿美元，其中包括第一季度与 H20 相关的 45 亿美元。

这些数字改变理解：平台权力并非无风险租金。越早锁定稀缺供应，越可能保证交付，也越可能在需求、政策或产品转换改变时承担库存和采购义务。

### Decision：与 Cloud Provider 合作，同时面对它们向上游进入

NVIDIA 通过 OEM、ODM、System Integrator 和 Cloud Provider 把平台送到终端客户。Cloud Provider 获得 Usage Data、Billing、Enterprise Contract、Region、Scheduler 和 Managed Service 关系；NVIDIA 获得 Processor、Networking、Software Ecosystem 与系统接口影响力。双方既互补又争夺边界。

Cloud Provider 自研 Accelerator 的动机由此出现：若能让特定 Workload 在自有硬件和软件上运行，它可以降低外购依赖、为客户提供差异化服务、改善单位经济性并把更多设计知识留在内部。但它必须重新承担 Architecture、Compiler、Library、HBM / Packaging Supply、Qualification 和 Developer Adoption；自研芯片不是把上游难题删掉，而是把边界向上游移动。

### Outcome：数据中心成为收入主体，但财务数字不能单独证明因果

NVIDIA FY2026 截至 2026 年 1 月 25 日：

- Total Revenue 为 2,159.38 亿美元；
- Data Center Revenue 为 1,937.37 亿美元，其中 Compute 1,623.61 亿、Networking 313.76 亿；
- Data Center 约占总收入 89.7%；
- 公司合并 Gross Margin 为 71.1%。

从 FY2017 的 8.30 亿到 FY2026 的 1,937.37 亿，Data Center Revenue 约为原来的 233 倍；同期 Total Revenue 约为原来的 31 倍，合并 Gross Margin 从 58.8% 增加 12.3 个百分点。这里的“倍数”只是两个财政年度端点之比，不能把九年内每次产品、AI 需求、定价、供给或会计变化压成单一原因。

这组数据与“利润池向加速计算平台显著移动”一致，但不能单凭收入和毛利率证明 CUDA、Mellanox、HBM 稀缺、AI Demand 或任何单一机制的独立因果贡献。Data Center Revenue 也可能通过位于台湾的直接客户开票而最终服务美国或欧洲客户，不能用 Billing Geography 直接推断最终需求位置。

### Aftermath：AWS Trainium 说明瓶颈和权力会继续迁移

AWS 2024 年 12 月发布 Trn2 Instance：每个 Instance 有 16 颗 Trainium2、1.5 TiB HBM、46 TB/s HBM Bandwidth 与 3.2 Tbps EFA Network。AWS 声称相对当时 GPU-based EC2 P5e / P5en，Trn2 提供 30–40% 更好的 Price Performance。这个百分比是供应商对指定产品比较的主张，不是所有模型、精度、Batch、软件和迁移成本下的独立普遍结论。

真正重要的是架构含义：AWS 没有只做芯片。它把 Trainium、Neuron Software、Instance、EFA、UltraCluster、Storage、Billing 和 Customer Contract 组合为服务。也就是说，下游客户关系持有者试图向上游建立自己的合格转换链。

但 Trainium2 仍需要 Logic Fabrication、HBM、Packaging、Server、Power 和 Network。若 Proprietary Accelerator 供给增加，瓶颈可能从 GPU 移到 HBM、Advanced Packaging、Power、Model Porting 或 Developer Time。竞争改变的是哪一层最难替代，不是让价值链消失。

## 8. Meaningful Comparison（有意义的对照）：NVIDIA 与 AWS 的“利润率”为什么不能直接比？

Amazon FY2025 披露 AWS Segment Sales 为 1,287.25 亿美元、Operating Income 为 456.06 亿美元，简单相除约 35.4%。NVIDIA FY2026 合并 Gross Margin 为 71.1%。把 71.1% 与 35.4% 排在一起宣布“上游比下游更赚钱”是错误的，因为：

- NVIDIA 的数字是 Consolidated Gross Margin，尚未扣除全部 R&D、SG&A 等 Operating Expense；
- AWS 的数字是 Segment Operating Income / Segment Sales，已经包含分配到该分部的更多运营费用；
- 两家公司财政年度、产品组合、Revenue Recognition 和 Segment Allocation 不同；
- AWS 采购的 NVIDIA 产品是多年资产的一部分，不是同年收入一一对应；
- NVIDIA 也通过 OEM、ODM 和 Distributor 销售，公开收入不是某家 Cloud Provider 的精确采购额。

更有意义的比较是双方各承担什么风险。Amazon 把部分 Server 与 Networking Equipment 的预计使用寿命从六年缩短到五年，理由是 AI / ML 技术发展加快；这使 2025 年 Depreciation and Amortization Expense 增加 14 亿美元、Net Income 减少 10 亿美元，主要影响 AWS。Cloud 层拥有客户，却也承担硬件快速过时和提前资本化的风险。

因此，NVIDIA 的平台毛利能力和 AWS 的客户关系都是真实权力来源；两者没有一张公开、同口径、同服务期的利润率表可以直接决定谁“赢走”一美元。

## 9. 反例：稀缺不总能变成长期利润

一家供应商可以在短缺时暂时不可替代，却因长期合同固定价格、客户双重采购、政府管制、技术标准开放或产能集中释放而无法保留持续超额回报。另一家公司也可能拥有优秀技术，却因为产量太小、良率低、软件不成熟、客户不愿重新资格化或需要承担过大资本风险而没有利润。

反过来，靠近终端客户也不保证获利。Cloud Provider 可能拥有 Billing 和 Usage Data，但若竞争迫使降价、资源利用率低、硬件折旧快、电力与机房扩张昂贵，客户关系产生的收入会被资本和运营成本吸收。

所以“Bottleneck 挣钱”只是需要检验的候选机制。还要问合同能否把稀缺转成价格、稀缺能持续多久、替代要花多久、谁承担扩产和需求反转风险，以及哪个口径下真的出现了利润。

## 10. Fact、Interpretation、Inference 与 Hypothesis

> **Fact（事实）**：NVIDIA 披露 FY2017 Datacenter Revenue 为 8.30 亿美元、总收入 69.10 亿美元；FY2026 Data Center Revenue 为 1,937.37 亿美元、总收入 2,159.38 亿美元，合并 Gross Margin 为 71.1%。NVIDIA 仍采用 Fabless / Contract Manufacturing。Amazon 披露 2025 年 AWS Sales 为 1,287.25 亿美元、Segment Operating Income 为 456.06 亿美元，并因部分服务器和网络设备使用寿命从六年改为五年而增加 14 亿美元折旧摊销费用。

> **Interpretation（解释）**：AI 数据中心的利润池显著向能够组合 Accelerator、Networking、System 与 Software 的平台移动；与此同时，Cloud Provider 仍通过客户、计费、资源池和自研芯片控制另一组关键接口。

> **Inference（推断）**：NVIDIA 从 Processor 向 Networking、System 和 Software 扩展，提高了客户替换整个平台的难度，并帮助公司把 Useful Compute 的更大部分纳入自己的产品边界。这个推断与公司产品和财务变化一致，但没有一个公开反事实告诉我们“若没有 CUDA 或 Mellanox，收入会是多少”。

> **Hypothesis（仍需验证的假设）**：未来利润池将永久留在 Accelerator Designer。若 Open Software、Custom Silicon、HBM / Packaging 扩产、Cloud Bargaining Power、Power Constraint 或模型效率改变替代成本，利润池可能向 Memory、Packaging、Energy、Cloud Software 或终端应用迁移。

### Evidence Boundary（证据边界）

- NVIDIA 和 AWS 文件是一手公司与监管披露，支持自身财务、产品和供应链陈述，不是对竞争优势的独立审计。
- FY2017 与 FY2026 是 NVIDIA 财政年度口径；AWS 采用截至 12 月 31 日的年度，不能把跨公司数字当同一交易期。
- NVIDIA Gross Margin 与 AWS Segment Operating Margin 不是同一费用层级；本课不做直接盈利能力排名。
- AWS 的 Trn2 Price-performance 是供应商对指定实例的比较；公开页面没有覆盖所有模型、精度、Porting、Utilization 和客户折扣。
- 128 节点、960 Accelerator、116 节点、100 设施节点和 85% 调度利用率全部是教学假设。
- 公开资料没有披露某一美元 Cloud Revenue 对应的 Wafer、HBM、Package、Server、Power、Software 与 Supplier Profit；本课只建立可核验的流和机制。

# Industry Apprenticeship（行业学徒制）

## 11. 今天只回答一个行业问题：一美元有用云服务收入怎样逆向连接整条产业链，哪里能保留利润？

先固定最终交付物：不是 FLOPS、GPU Hour 或 Rack，而是满足正确性、延迟、吞吐、可用性和支持边界的 Useful Cloud Service。然后逐层问三件事：本层接收什么、交付什么、哪个事实使交付失败？

| 层级 | 交付的合格对象 | 主要付款方 | 可能保留利润的控制点 | 主要翻转条件 |
|---|---|---|---|---|
| Cloud Software / Service | 可计量、可到达、满足 SLO 的业务能力 | End Customer | Billing、Usage Data、Distribution、Managed Service、Contract | 价格竞争、低利用率、开源替代、客户自建 |
| Data Center / Network | 可持续供电、冷却、联网并已 Commission 的容量 | Cloud / Tenant | 土地、电力、许可、互联、位置、交付速度 | 新电源与园区、技术密度变化、网络替代 |
| Server / Rack Integration | 通过系统验证、可支持的 Node / Rack | Cloud / OEM Customer | Firmware、拓扑、验证、供应整合、Warranty | 标准化、ODM 竞争、客户自行集成 |
| Accelerator Platform | Useful Throughput 与软件可用性 | OEM / CSP / Enterprise | Architecture、CUDA / Library、Interconnect、Developer Ecosystem | Custom Silicon、开放软件、Porting 能力 |
| HBM / Packaging | 合格 Stack、互连封装和 Final-good Package | Chip Designer / Packager | 高良率、TSV / Bonding、合格产能、热与测试知识 | 扩产、替代内存、设计减少带宽需求 |
| Foundry / Fabrication | 满足规格和良率的 Good Die | Fabless / IDM Product Group | Process、Yield Learning、Capacity、Qualification | 节点成熟、第二来源、需求下降 |
| Wafer / Equipment / Materials | 稳定、合格的制造输入与 Process Capability | Foundry / IDM | 专用设备、材料纯度、安装基础、服务与资格记录 | 新供应商资格化、产能释放、工艺替代 |

**Profit Pool（利润池）**第一次正式出现时要这样理解：历史上产业分析用它避免把 Revenue 最大误认为 Profit 最大；付款方沿采购链支付，但真正受益的是能判断产业权力、投资回报和战略边界的人。它解决“哪一层保留经济剩余”，不是“哪一层对工程最重要”。常见误解是用一家公司的毛利率代表整层利润，或把短期短缺溢价当永久护城河。

**Scarcity Rent（稀缺回报）**在这里不是要求记忆的新节点，只是白话机制：当一项合格能力在当前必须使用、替代很少、扩产很慢时，供应者可能获得高于普通竞争状态的回报。付款方是急需该能力的下游，受益方是控制合格供给者；它解决短期供需不匹配，常见误解是把它等同于非法垄断，或认为稀缺必然长期存在。

行业判断不应停在“谁毛利最高”。还要追踪：

- Marginal Capacity 增加在哪层最能提高 Successful Useful Output？
- 谁拥有 Design / Software / Qualification / Capacity / Customer 数据？
- 谁需要预付款或长期合同，谁承担 Demand Reversal？
- 替代一层需要多少 Porting、Retooling、Qualification 与 Deployment Time？
- Revenue、Gross Profit、Operating Profit、Free Cash Flow 与 Return on Invested Capital 分别说明什么？

## 12. Transfer（迁移）：以后看到“AI 芯片利润会被云厂商拿走”，怎样拆？

先指定工作负载与服务边界。Training、Batch Inference、Low-latency Inference、Recommendation 和 HPC 的 Memory、Network、Software 与 Reliability 条件不同，不能用一个 Accelerator Market 结论覆盖全部。

再画替代路径：更换芯片是否只换硬件，还是要改 Compiler、Library、Framework、Model、Kernel、Rack、Network、Cooling 和 Operations？每一项需要多久，谁付款，谁验证正确性？

然后寻找瓶颈迁移证据：加更多 Accelerator 后 Useful Throughput 是否增加？若 HBM、Network、Power 或 Model Porting 成为新约束，新增芯片不再是最有价值的边际投资。

最后才比较利润。统一财政期、费用口径和资本边界，区分供应商 Revenue、客户 Capex、Provider Depreciation 与终端 Service Revenue。没有可比口径时，保留方向和翻转条件，不制造精确分账。

## 14. 现在我们可以重新回答开头的问题

客户把钱付给 AWS，NVIDIA 仍可能保留巨大价值，因为最终服务必须经过 Accelerator、Interconnect、Networking 与 Software 的合格转换，而这些接口短期难以替换；Cloud Customer Relationship 没有消除上游平台的不可替代性。AWS 仍开发 Trainium，因为客户、计费、调度和工作负载数据让它有动机把芯片设计与软件边界向上游延伸，降低依赖并争取更多系统价值。

两者都没有控制整条链。NVIDIA 依赖 Foundry、Memory、Packaging、Server 与 Cloud Deployment，并为供应和产品转换承担巨额承诺；AWS 自研芯片仍依赖同样的制造、HBM、封装、电力和网络，还要建立软件与开发者采用。利润池不是按产业位置固定分配，而是跟随当前最难替代的合格能力、关键接口、切换延迟、客户关系和风险承担迁移。
