**Module Orientation（模块定位）**：Artificial Intelligence 模块研究 AI System 怎样把合格数据变成模型状态，再把模型状态变成真实世界能力。母概念 **Trained Model（已训练模型）** 是架构、词表或输入表示、学得的参数值及必要配置共同构成的函数状态；Checkpoint 是它在某一训练时刻的可恢复快照。今天教授 Foundation Model 这类已训练模型的一个核心性质：它先从广泛数据中形成可复用表示，再经下游适配变成具体任务模型。先把 Pretraining、Transfer 与 Adaptation 分开，下一课才有资格讨论参数固定后一次 Inference 怎样产生输出；否则会把“训练得到的共同起点”“为任务改造的版本”和“用户此刻得到的回答”混成同一个对象。

> **今天如果只记住一件事，就是：基础模型不是一个已经完成所有任务的万能产品，而是一份在广泛数据上预训练出的共享参数起点；Transfer 是把其中可复用的表示带到新任务，Adaptation 则用新数据、目标或上下文把共同起点变成合格的任务能力。**

# Mastery Core（掌握核心）

## 1. Opening Puzzle（开场谜题）：同一个文件，为什么能变成三种不同模型？

2018 年末，一名开发者下载了 Google 发布的 BERT Checkpoint。文件里的参数值只有一份。她复制三份：第一份用于判断电影评论是正面还是负面；第二份用于从一段文章里找出问题答案的起点和终点；第三份用于给句子中的人名、地点和机构贴标签。

三份起点完全相同，最终输出形状、标签、训练数据和评价指标却不同。它们显然不是同一个产品；但它们也不需要从随机参数重新学习英语里的词序、上下文和句间关系。

这里的谜题不是“一个模型会多少任务”，而是：**一份参数状态中，什么东西能够跨任务复用；什么东西仍必须为任务重新学习？**

## 2. 先定义母概念：Model State、Foundation Model 与 Task Model

**Model Architecture（模型架构）**规定信息怎样流动，例如 BERT 使用多层双向 Transformer Encoder。**Parameters（参数）**是在训练中被更新的大量数值。架构像一套可调机器，参数状态决定这台机器此刻实现的具体映射。只说“Transformer”没有指出学到了什么；只拿到参数而没有匹配的架构、词表和输入规则，也不能正确运行。

2021 年 Stanford CRFM 把 **Foundation Model（基础模型）**定义为：在广泛数据上、通常以大规模自监督方式训练，并能适配到广泛下游任务的模型。“Foundation”强调它既处于中心位置、又是不完整的地基：它能降低许多任务的起步成本，但不是部署完成证书。

为了不把三个动作混为一谈：

- **Pretraining（预训练）**：在具体下游任务确定或使用之前，用广泛数据和可大规模生成的训练目标形成共享参数状态。付款方通常是模型开发者；受益者是后来不必从随机参数起步的多个任务团队。它解决“每个任务都要重新学习一般结构”的浪费；常见误解是 Pretraining 等于把互联网原文完整存进模型，或预训练损失低就证明所有任务都可用。
- **Transfer（迁移）**：下游任务从预训练参数、表示或行为中获得起点优势。Transfer 描述的是能力或统计结构被复用的关系，不必然意味着参数已经改变。它解决“过去学到的结构能不能减少新任务的数据与计算”；常见误解是复制 Checkpoint 文件本身就证明迁移成功。
- **Adaptation（适配）**：为特定任务、领域、用户或约束改变模型、输入上下文或附加组件，使共同起点满足新的目标。Fine-tuning 是适配的一种；固定参数后训练一个输出层、Adapter / LoRA、提示与示例、检索增强也可以属于更广义的适配。付款方可以是模型供应商、应用开发者或客户；受益方是具体工作流。它解决共同模型与具体任务之间的最后一段差距；常见误解是适配必然要更新全部参数，或适配后不需独立评价。

**Task Model（任务模型）**则是基础模型经过某种适配后，连同任务输入、输出、数据、阈值与评价边界形成的具体候选。一个 BERT Checkpoint 可以是三个任务模型的祖先，却不是三个任务模型本身。

## 3. Follow One Unit（跟随一个最小单位）：一个 `[CLS]` 向量怎样从共同起点变成情感判断？

输入一句话：“这部电影慢得令人着迷。”BERT 先把文本切成 WordPiece Token，并在最前面加入特殊 Token `[CLS]`。每层双向注意力让一个 Token 的表示同时受左右上下文影响，所以“慢”不会永远等于负面；它会与“令人着迷”共同改变最后一层的上下文表示。

预训练时，BERT 并没有收到“电影评论正面”这个标签。它随机选取 15% 的 Token 位置做预测目标：其中 80% 换成 `[MASK]`、10% 换成随机 Token、10% 保持原样，并要求模型恢复原 Token；它还判断第二段文字有 50% 是真实下一段、50% 是随机段。大量训练步使参数逐渐编码哪些词与上下文相容、哪些句段关系常见。

当开发者把同一个 Checkpoint 用于情感分类时，她在 `[CLS]` 表示上添加一个很小的分类输出层，并用有标签评论计算新损失。BERT 论文的做法会端到端更新全部参数：共同起点仍在，但参数被推向“在这个数据集上区分标签”的新位置。这个过程就是一种 Fine-tuning；真正的 Transfer 要由相对于从随机初始化或其他起点的下游表现证明，而不是由“加载成功”证明。

问答任务则不同。它不把 `[CLS]` 直接变成正负标签，而是让每个 Token 的表示竞争答案起点与终点。命名实体识别又为每个 Token 预测类别。共同参数提供上下文表示，任务输出层、标签和损失说明这些表示这次要被怎样使用。

所以最小机制是：**共享参数提供可复用表示空间；任务接口把新问题翻译成输出；适配信号重新分配参数或附加组件；独立评价决定迁移是否真的发生。**

## 4. Main Case — BERT：一份预训练参数怎样成为多个 NLP 任务的共同起点

### Before：每个任务都像一座单独修建的房子

在通用预训练成为主流以前，情感分类、自然语言推断、命名实体识别和问答往往使用不同特征、结构与训练流程。每个任务的有标签数据相对稀缺，却要重复学习词义、句法和上下文。词向量可以复用，但同一个词在 “bank deposit” 与 “river bank” 中常共享一份静态表示，不能充分表达语境。

### Pressure Builds：广泛无标签文本很多，有标签任务数据却各自狭窄

BooksCorpus 约 8 亿词，英语 Wikipedia 约 25 亿词，合计约 33 亿词。它们没有为每句话人工标注情感、答案跨度或实体类型，但文本本身能制造训练信号：遮住一个词就有原词可作为目标，相邻段落也能构造关系判断。

这里的规模对照改变理解。BERT 论文的 GLUE 任务训练集从 RTE 约 2,500 个样本到 MNLI 约 392,000 个样本，而预训练面对的是数十亿词。预训练不是把一个大标签集拆给所有任务；它先利用廉价、广泛但目标较粗的信号，形成下游能够再解释的表示。

### Turning Point：同一架构先学广泛上下文，再用同一参数初始化不同任务

BERT Base 有 12 层、隐藏维度 768、12 个注意力头和约 1.10 亿参数；BERT Large 有 24 层、隐藏维度 1,024、16 个注意力头和约 3.40 亿参数。团队用 Masked Language Modeling 与 Next Sentence Prediction 预训练；随后，不同任务都从同一套预训练参数开始，只更换最末端的任务输入输出，并在 BERT 实验中端到端 Fine-tune 全部参数。

这一步的关键不是 3.40 亿比 1.10 亿“大”，而是参数用途改变了：预训练目标没有直接要求它输出 SQuAD 的答案跨度，却迫使同一表示同时利用左右上下文；任务适配再把这种表示压向答案边界、类别或 Token 标签。

### Cascade：一次昂贵训练被拆成许多较小的适配实验

论文以 Batch 256、最多 512 Token 的序列训练 100 万步，作者估算约相当于 33 亿词语料的 40 个 Epoch。为降低注意力对长序列的二次方成本，90% 步骤使用长度 128，最后 10% 才使用长度 512。BERT Base 用 16 个 TPU 芯片、Large 用 64 个 TPU 芯片，各约四天完成预训练。

下游适配的资源边界明显不同。作者称，从同一预训练模型开始，论文中的 Fine-tuning 任务在一张 Cloud TPU 上最多约一小时，SQuAD 示例约 30 分钟达到 Development F1 91.0。四天与半小时不是完整成本比较：TPU 数量不同，数据准备、超参数搜索、失败运行和评价没有统一计入；但它显示了共享起点怎样把“每个任务都重新做广泛学习”改成“一次预训练，多次较小适配”。

### Decision：统一模型主体，只让任务边界发生最小变化

团队没有为每个任务重新设计主体网络。句子分类读取 `[CLS]`；问答对每个 Token 预测开始和结束；序列标注对每个 Token 分类。论文称任务模型只增加一个输出层，绝大多数结构来自共同 BERT。

这个决定创造了工程杠杆：模型团队发布 Checkpoint 与代码，任务团队用自己的标签和评价完成最后一段。但它也制造共同故障源：若共同参数携带数据偏差、语言覆盖缺口或脆弱表示，多个下游任务都可能继承。

### Outcome：共同起点在多类任务上产生了可测的下游收益

BERT Large 在论文列出的 GLUE Test 平均为 82.1，BERT Base 为 79.6，OpenAI GPT 为 75.1；平均值排除了当时有问题的 WNLI，且各列混合 Accuracy、F1 与 Correlation，不能把 82.1 读作“82.1% 通用语言理解”。它是同一评测集合下的汇总比较。

SQuAD 1.1 上，带 TriviaQA 额外适配的 BERT Large 单模型 Test F1 为 91.8，七模型 Ensemble 为 93.2；后者不是一份共享 Checkpoint 的单次结果，也包含模型集成与额外数据。SQuAD 2.0 单模型 Test F1 为 83.1，相比当时列出的 78.0 最佳单模型高 5.1 个百分点。SWAG Test Accuracy 为 86.3，对 OpenAI GPT 的 78.0 高 8.3 个百分点。不同任务、数据和指标不能相加成“模型能力总分”，但共同起点跨句子级、句对级、Token 级和答案跨度任务成功适配，正是 Foundation Model 机制的早期清晰证据。

### Aftermath：Foundation 的杠杆与共同风险同时扩大

Google 发布了 BERT Base / Large 的 Cased 与 Uncased Checkpoint 和 Fine-tuning 代码。研究者不必重做原始预训练，就能从相同参数状态开始实验。2021 年 Foundation Model 报告用 BERT、GPT-3 与 CLIP 说明新的范式，并特别强调 Homogenization：共同模型让许多任务共享改进，也让一个地基缺陷沿许多下游系统传播。

BERT 的具体设计也没有成为永恒真理。原论文的消融实验支持 NSP 对当时若干任务有帮助，但后续模型可以采用不同目标和数据配方。正确迁移结论不是“BERT 的每个组件都普遍最优”，而是：**广泛预训练形成的参数状态，经过有边界的任务适配，能比每项任务从零开始更有效地建立能力。**

## 5. Meaningful Comparison（有意义的对照）：四个经常混在一起的对象

| 对象 | 最小问题 | 参数是否一定改变 | 成功证据 |
|---|---|---:|---|
| Pretraining | 怎样从广泛数据形成共同参数起点？ | 是 | 预训练目标、保留评价、可复用表示与完整训练记录 |
| Transfer | 共同起点是否帮助了新任务？ | 不一定 | 与合理起点对照后的数据效率、质量、稳健性或成本改善 |
| Adaptation | 怎样让共同起点符合具体任务、领域或用户？ | 不一定 | 明确适配方法、数据、版本、任务评价与失败边界 |
| Inference | 给定当前参数和输入，此刻输出什么？ | 通常否 | 输出质量、延迟、成本、稳定性与服务约束；下一课正式教授 |

再比较三种起点：随机初始化从零开始学习；Feature Extraction 固定基础参数，只把表示交给新输出层；Full Fine-tuning 从预训练参数开始并更新全部参数。前者没有 Transfer，后两者都有可能发生 Transfer，但成本、遗忘、数据要求和任务控制不同。没有一个方法在所有任务上天然最优。

## 6. 反例：同一基础模型能适配很多任务，是否证明它已经理解所有任务？

不证明。第一，适配成功依赖下游数据与接口：没有可靠标签、任务定义或评价，参数起点再强也无法给出验收结论。第二，Transfer 可以是负的：预训练分布、目标和下游需求不匹配时，共同表示会带来错误先验。第三，适配可能破坏原有能力或放大偏差；多个任务从同一地基出发，也会共享相关故障。

更重要的是，Benchmark 改善不等于部署价值。SQuAD 答案来自给定段落，不能证明模型能验证现实事实；GLUE 汇总不能说明医疗、法律或少数语言的可靠性；Fine-tuning 一小时也没有计入收集标签、搜索超参数、红队、安全审查、服务推理和持续维护。

## 7. Fact、Interpretation、Inference 与 Hypothesis

> **Fact（事实）**：BERT 使用约 33 亿词的 BooksCorpus 与英语 Wikipedia，Base / Large 分别约 1.10 亿 / 3.40 亿参数；论文从同一预训练参数初始化 11 个 NLP 任务，并报告预训练约四天、许多下游 Fine-tuning 在一张 Cloud TPU 上不超过一小时。

> **Interpretation（解释）**：Masked LM 迫使共享参数利用双向上下文形成可复用表示；任务输出层和下游损失再决定这些表示如何服务分类、标注或答案跨度。

> **Inference（推断）**：跨任务表现与较小的任务专用改动支持“共同参数起点降低下游起步成本”，但公开数据不足以把收益精确分解为语料规模、双向架构、目标、参数量和超参数搜索各自贡献。

> **Hypothesis（仍需验证的假设）**：对一个新的专业领域，继续使用通用 BERT 并做轻量适配，会比从零训练或全量 Fine-tuning 获得更低的合格结果总成本。验证需要固定数据、评价、硬件、搜索预算与失败运行，并比较质量、稳健性、延迟和维护成本。

### Evidence Boundary（证据边界）

- BERT 是 2018–2019 年的 Encoder 模型案例，不代表现代生成式、多模态或闭源基础模型的全部机制。
- 论文把 Masked LM 与 NSP、架构、语料规模和训练配方组合使用；Benchmark 结果不能把全部收益归因于单一组件。
- “四天预训练、最多一小时 Fine-tuning”来自作者环境，TPU 数量、任务、搜索与工程边界不同，不能直接变成统一价格或能耗比。
- SQuAD 1.1 的 93.2 F1 是七模型 Ensemble 加 TriviaQA；单模型加 TriviaQA 为 91.8，不能混写。
- GLUE 82.1 是混合指标的汇总并排除 WNLI，不是 82.1% 的通用理解概率。
- Foundation Model 一词的 2021 定义描述广泛数据与广泛适配性，不保证模型正确、安全、合法、无偏或已部署。
- 同一 Checkpoint 的文件复用不证明有效 Transfer；必须有下游对照、独立评价与真实服务边界。

# Industry Apprenticeship（行业学徒制）

## 8. 今天只回答一个行业问题：模型公司为什么愿意承担一次昂贵 Pretraining，而下游客户仍要为 Adaptation 付款？

因为两笔钱购买的是不同对象。Pretraining 把广泛数据、计算、研究与失败实验汇聚成一份可复用参数资产；它把多个潜在任务的共同学习成本集中承担。Adaptation 则购买任务定义、专有数据、领域接口、评价、安全、版本维护与服务约束，把“可能有用的共同起点”变成“对这个客户合格的能力”。

BERT 提供了早期清晰版本：Google 承担四天、16 或 64 个 TPU 芯片的预训练，并发布 Checkpoint；下游团队可以在相同起点上用自己的数千到数十万条标签完成较短 Fine-tuning。预训练成本并没有消失，而是由一个上游资产跨更多任务摊销；下游成本也没有消失，因为标签、选择、搜索、评价与部署不可由共享参数替代。

今天第一次完整使用四个行业词：

- **Model Checkpoint（模型检查点）**：参数和必要状态的版本化快照。历史上它解决长训练中的恢复与比较；提供者生成并保存，下游团队据此初始化。它不是模型许可证、完整产品或质量保证。
- **Fine-tuning（微调）**：从已训练参数开始，用下游目标继续更新部分或全部参数。付款方通常是模型或应用团队，受益者是具体任务；它减少从零训练，却可能过拟合、遗忘或引入新风险。常见误解是 Fine-tuning 等于全部 Adaptation。
- **Model API（模型接口）**：供应商托管模型并按请求、Token、容量或合同开放能力。它解决客户无需拥有权重和推理设施的问题；客户支付使用与服务边界，供应商保留模型与运营控制。常见误解是 API 使用等于客户拥有 Checkpoint，或一次调用会自动训练底层模型。
- **Downstream Task（下游任务）**：在共同预训练之后，用具体输入、输出、目标和评价定义的工作，例如情感分类或答案抽取。它提醒买方基础模型价值必须落到任务分母；常见误解是 Benchmark 任务天然代表真实工作流。

一个透明经济模型：一次 Pretraining 总成本假设为 1,000 万元，并产生一个合格共同起点。若只服务一个任务，全部共同成本都压在该任务上；若 100 个独立任务都成功复用，简单平均为每项 10 万元。但若其中只有 20 项通过下游评价，则按合格任务分母为每项 50 万元。每项再花 8 万元做数据、适配与评价，总计约 58 万元。这里所有数字都是教学假设，不是 BERT、Google 或任何供应商账单；它只说明摊销必须除以合格任务，而不是下载次数。

| 参与者 | 控制或交付什么 | 收入 / 成本 / 风险 |
|---|---|---|
| Foundation Model Developer | 数据混合、目标、架构、预训练、Checkpoint 与发布边界 | 承担高前置成本和研究失败；通过许可证、API、云消费或生态影响回收 |
| Cloud / Infrastructure Provider | 训练和推理资源、存储、网络与可用性边界 | 按资源或服务收费；一般不保证下游任务一定迁移成功 |
| Application / Adaptation Team | 任务定义、专有数据、适配、评价、工作流与上线 | 为最后一公里付款；承担任务错配、质量、安全和维护风险 |
| Customer / End User | 业务反馈、真实约束和付款 | 获得具体服务，不自动获得权重、训练数据或修改权 |
| Affected Public / Rights Holders | 内容、被表示群体和外部影响 | 可能并未直接收款，却可能承担隐私、偏差、劳动力和信息风险 |

谁能保留利润，取决于稀缺性和控制权：独特且可靠的共同模型、专有数据、低成本推理、分发入口、客户工作流、评价能力和 Switching Cost 都可能成为利润池。公开 BERT 案例证明技术杠杆，不足以推出今天某家公司的利润率、私有数据权利、API 价格或客户总成本。

## 9. Transfer（迁移）：看到“我们使用了某个基础模型”时怎样审计？

先问共同起点是什么版本、架构、词表、数据与目标；再问 Transfer 的证据来自什么合理对照；然后问 Adaptation 改了参数、附加组件还是输入上下文，使用了哪些数据与权限；最后固定下游任务、评价集、服务质量、延迟、成本、安全与回滚边界。只要这些没有写清，“用了最强基础模型”就还不是能力结论。

## 10. Teach-back（20–30 分钟）

### 问题一：重建同一个 Checkpoint 的三条路径

不用“模型已经学会语言”这句话。请从同一 BERT Checkpoint 出发，分别解释它怎样成为情感分类、答案抽取与命名实体识别候选；指出哪些对象被复用、哪些对象为任务新增或改变，以及什么证据才算 Transfer 成功。

### 问题二：审计一项商业主张

一家供应商说：“我们把一次 1,000 万元预训练成本摊给 100 个客户，所以每个客户的模型成本只有 10 万元。”请指出至少五个缺失分母或边界，并解释哪些成本和风险仍停留在 Adaptation、Evaluation、Inference 与客户工作流。

## 11. 现在我们可以重新回答开头的问题

同一个 BERT 文件能成为三种不同模型，因为预训练参数并没有直接储存三项产品，而是形成了可复用的上下文表示起点。情感分类读取 `[CLS]` 并增加分类目标；问答对 Token 预测答案边界；实体识别对 Token 贴类别。每个任务都从相同参数开始，却用自己的接口、数据、损失和评价把参数推向不同状态。

BERT 的约 33 亿词、100 万步和四天预训练说明共同起点需要真实成本；下游在一张 TPU 上几十分钟到一小时说明这种成本可以被多个任务复用；GLUE、SQuAD 和 SWAG 的结果说明迁移在这些边界内发生了，却不证明通用正确、安全或零成本部署。
